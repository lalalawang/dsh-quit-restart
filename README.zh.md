# dsh-quit-restart

[English](README.md)

在 DSH 侧边栏加一行「退出并重启 DSH」。点一下，应用关掉，然后自己回来。

不用再去托盘退出、再自己找快捷方式打开。

## 安装

应用内：左侧栏「插件」→ 添加插件，填 `dsh-quit-restart`（npm）或 `https://github.com/lalalawang/dsh-quit-restart`。

装完重启一次 DSH。插件只在启动时扫描，不重启看不到。

## 使用

侧边栏最下面一行，和「设置」并排，写着「退出并重启 DSH」。

点一下，按钮变成「正在退出…」，然后页面断开、应用重新起来。没有其他要配的东西。

## 它到底做了什么

Windows 上，一段一次性 VBS 脚本被写进 `%TEMP%`，用 `wscript.exe` 脱离启动，跑完自删。脚本干三件事：

1. `taskkill` 结束**两个**进程：Electron 主进程，和跑这个插件的宿主进程。
   只杀主进程不行。宿主是它的子进程，会一直占着端口，新实例起不来。
2. 每 250ms 查一次这两个 PID 还在不在，最多等 10 秒。还没退就按进程名兜底再杀一次。
3. 清掉继承来的 `ELECTRON_RUN_AS_NODE`（不清的话新进程会以 node 模式启动、不出界面），然后用原来的 exe 启动应用。

整个过程不弹控制台窗口。

## 接口

宿主半身注册了两条路由：

| 路由 | 作用 |
| --- | --- |
| `GET /api/quit-restart/status` | 返回找到的 exe 路径、从哪找到的、主进程 PID、平台是否支持 |
| `POST /api/quit-restart/restart` | 带 `{"dryRun": true}` 只解析不执行；否则开始重启 |

两条都只接受本机回环地址的请求。带了 `Origin` 的，必须和当前服务同源，否则返回 `403`。非 Windows 返回 `501`。

## 找不到 exe 路径

正常情况会从父进程镜像路径推断出来，不写死任何路径。

如果推断失败（比如从别的方式启动），设环境变量 `DSH_QUIT_RESTART_APP_EXE` 为完整路径。

## 出问题时

日志在 `%TEMP%\dsh-quit-restart-<pid>-<时间>.log`，每一步都有记录，能看到卡在哪。

按钮显示「重启失败」通常是杀进程那步没权限。看日志里最后一行。

## 注意

- 重启会中断正在生成的回答。会话记录已经在磁盘上，不会丢。
- 重启后的应用是独立进程，关掉启动它的终端不影响它。
